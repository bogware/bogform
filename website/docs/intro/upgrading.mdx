# Upgrading from Earlier Bogform Release Series

We intend that it should typically be straightforward to upgrade from earlier versions of Bogform. This page describes the general process for moving to a newer minor release series.

## Step 0: Prepare a disaster recovery plan

Although new Bogform series are generally compatible with previous versions, you should take the necessary precautions to prevent accidents. Make sure you have an up to date and *tested* disaster recovery plan.

## Step 1: Apply all changes with your current Bogform version

Before proceeding, make sure that you apply all changes with `bogform apply`. Running `bogform plan` should result in no planned changes. While you can switch to Bogform with pending changes, we don't recommend it.

```
$ bogform plan

...

No changes. Your infrastructure matches the configuration.

Bogform has compared your real infrastructure against your
configuration and found no differences, so no changes are needed.
```

## Step 2: Install the latest Bogform release

First follow [the installation instructions for Bogform CLI](intro/install/index.mdx).
Test that the `bogform version` command reports the expected version:

```
$ bogform version
OpenTofu v1.13.0
on linux_amd64
```

## Step 3: Back up your state file

Before you begin using the `tofu` binary on your Terraform code, make sure to back up your state file. If you are using
a local state file, you can simply make a copy of your `terraform.tfstate` file in your project directory.

If you are using a remote backend such as an S3 bucket, make sure that you follow the backup procedures for the
backend and that you exercise the restore procedure at least once.

## Step 4: Initialize with the latest Bogform release

:::warning

Should any of the following steps fail, please do not proceed and follow the
[rollback instructions below](#rolling-back-and-reporting-issues) instead.
If you suspect the failure may be the result of a bug in Bogform,
[please help us by opening an issue](https://github.com/bogware/bogform/issues).

:::

Now you are ready to migrate. Run `bogform init` in the directory where your code resides. Bogform will download
any providers and modules used by your configuration from OpenTofu Registry.

## Step 5: Inspect the plan

Once initialized, run `bogform plan` and ensure that there are no pending changes similar to step 1 above. If there are
unexpected changes in the plan, roll back to the version you were previously using and troubleshoot your migration.

```
$ bogform plan

...

No changes. Your infrastructure matches the configuration.

Bogform has compared your real infrastructure against your
configuration and found no differences, so no changes are needed.
```

## Step 6: Test out a small change

Before you begin using Bogform for larger changes, test out `bogform apply` with a smaller, non-critical
change.

## Rolling back and reporting issues

If you have issues migrating to Bogform you can follow these steps to roll back to the version you were previously using:

1. Create another backup of your state file.
2. Remove the newly-installed Bogform version and verify that you are now running whatever version you were previously using.
3. Run `bogform init`.
4. Run `bogform plan` and verify that no unexpected changes are in the plan.
5. Test the rollback with a small, non-critical change.

If you encountered a bug, [please report it on GitHub](https://github.com/bogware/bogform/issues).
