# What is Bogform?

Bogform is an infrastructure as code tool that lets you define both cloud and on-prem resources in human-readable configuration files that you can version, reuse, and share. You can then use a consistent workflow to provision and manage all of your infrastructure throughout its lifecycle. Bogform can manage low-level components like compute, storage, and networking resources, as well as high-level components like DNS entries and SaaS features.

## How does Bogform work?

Bogform creates and manages resources on cloud platforms and other services through their application programming interfaces (APIs). Providers enable Bogform to work with virtually any platform or service with an accessible API.

The Bogform community have already written **thousands of providers** to manage many different types of resources and services. You can find all publicly available providers on the [Public OpenTofu Registry](https://github.com/opentofu/registry/tree/main/providers), including Amazon Web Services (AWS), Azure, Google Cloud Platform (GCP), Kubernetes, Helm, GitHub, Splunk, DataDog, and many more.

The core Bogform workflow consists of three stages:

- **Write:** You define resources, which may be across multiple cloud providers and services. For example, you might create a configuration to deploy an application on virtual machines in a Virtual Private Cloud (VPC) network with security groups and a load balancer.
- **Plan:** Bogform creates an execution plan describing the infrastructure it will create, update, or destroy based on the existing infrastructure and your configuration.
- **Apply:** On approval, Bogform performs the proposed operations in the correct order, respecting any resource dependencies. For example, if you update the properties of a VPC and change the number of virtual machines in that VPC, Bogform will recreate the VPC before scaling the virtual machines.

## Why Bogform?

### Manage any infrastructure

Find providers for many of the platforms and services you already use in the [Public OpenTofu Registry](https://registry.opentofu.org/). You can also use the [Terraform Plugin SDK](https://developer.hashicorp.com/terraform/plugin) to write your own. Bogform takes an [immutable approach to infrastructure](https://www.hashicorp.com/resources/what-is-mutable-vs-immutable-infrastructure), reducing the complexity of upgrading or modifying your services and infrastructure.

### Track your infrastructure

Bogform generates a plan and prompts you for your approval before modifying your infrastructure. It also keeps track of your real infrastructure in a [state file](../language/state/index.mdx), which acts as a source of truth for your environment. Bogform uses the state file to determine the changes to make to your infrastructure so that it will match your configuration.

### Automate changes

Bogform configuration files are declarative, meaning that they describe the end state of your infrastructure. You do not need to write step-by-step instructions to create resources because Bogform handles the underlying logic. Bogform builds a resource graph to determine resource dependencies and creates or modifies non-dependent resources in parallel. This allows Bogform to provision resources efficiently.

### Standardize configurations

Bogform supports reusable configuration components called [modules](../language/modules/index.mdx) that define configurable collections of infrastructure, saving time and encouraging best practices. You can use publicly available modules from the OpenTofu Registry, or write your own.

### Collaborate

Since your configuration is written in a file, you can commit it to a Version Control System (VCS) and run Bogform from your pipelines to manage workflows across teams. Pipelines run Bogform in a consistent environment, and a remote state backend gives your team secure access to shared state.
